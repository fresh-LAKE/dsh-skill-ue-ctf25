# CF_CNCV25_EVENTS 二进制格式（实测整理）

本文是把 `references/original-code/*.json`（以及 `validated-mario-bw1.json`）里
`CF_CNCV25_EVENTS` 载荷逐字节拆开后得到的结构说明。所有结论都来自本仓库样本，
未在其它 Fusion 版本上验证。**未知字段不要猜，按“从最接近的样本复制”处理。**

## 1. 包整体

| 偏移 | 内容 |
|---|---|
| 0x00 | `KLBEDAEH` |
| 0x08 | u32 版本，样本恒为 `06 04 01 00` |
| 0x0C | u32 未知（样本 0x20 / 0x30 / 0x31；小体积帧事件用 0x30，`mario-movement`、`process-start` 这类大部头是 0x31） |
| 0x10 | `STVE` |
| 0x14 | u32 事件流字节数 |
| 0x18 | 事件流（长度见上），以 `00 00` 结尾 |
| 之后 | 元数据：`SMER` → `SJBO` → `TYAL` → `!DNE` |

`0x0C` 的含义未确定；生成新包时直接沿用同一类样本的值（小包用 0x30）。

## 2. 事件流

事件流 = 若干事件记录 + `00 00` 终止符。

### 2.1 事件头（14 字节，小端）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | i16 | 记录总长的**负数**（含头部） |
| 2 | u8 | 条件数 |
| 3 | u8 | 动作数 |
| 4 | u16 | 标志：0x8000 = 位于父事件之下（嵌套）；顶层为 0。另有 0x0040/0x2000 出现，含义未定 |
| 6 | u16 | 未定（样本 0、0x20、0xFC、17、21、32、42、126…）；普通事件填 0 |
| 8 | u16 | 层级字段：可反映组和子事件层级；非零不等于子事件，须结合 `0x8000` 标志判断 |
| 10 | u16 | 事件 id，从 1 递增 |
| 12 | u16 | 前一个事件的 id；第一个事件为 0 |

紧接 14 字节头就是“条件×N + 动作×M”的记录序列。

### 2.2 条件记录（16 字节头）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u16 | 记录总长（含头与参数） |
| 2 | i16 | 对象类型（见 §4） |
| 4 | i16 | 条件 opcode（见 cookbook） |
| 6 | u16 | 对象 id（SJBO 里的 id，不是序号） |
| 8 | u16 | 0 |
| 10 | u16 | 条件标志：普通 0x0020；**取反 0x0120**（bit 0x0100 = NOT）；按键触发 `(-7,-4)` 与独立 NOT 记录 `(-1,-25)` 为 0 |
| 12 | u8 | 参数个数 |
| 13 | u8 | 未定（样本均为 0） |
| 14 | u16 | 0 |

**取反有两种表示**：条件头偏移 10 的 u16 的 `0x0100` 位，或独立的 `(-1,-25)` NOT 记录。
`NOT Mario is overlapping Group.Water` 在 `mario-movement` 里用的是前一种
（`#167`、`#172`），而 `#182` 附近又出现独立 NOT 记录。两种都能被 Fusion 读出，
生成时优先用**同一份导出里的写法**（`ctf_events.py describe` 会把取反显示成 `NOT`）。

### 2.3 动作记录（14 字节头）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u16 | 记录总长 |
| 2 | i16 | 对象类型 |
| 4 | i16 | 动作 opcode |
| 6 | u16 | 对象 id |
| 8 | u16 | 0 |
| 10 | u16 | 0 |
| 12 | u8 | 参数个数 |
| 13 | u8 | 0（头部最后一个字节，样本均为 0） |

### 2.4 参数

`u16 总长（含 4 字节头）` + `u16 类型` + 内容。常见类型：

下表字节数和偏移均相对于参数内容（body），不含 4 字节参数头。

| 类型 | 用途 | 备注 |
|---|---|---|
| 1 | 对象指针 | 8 字节：`00 00 <目标对象id u16> 02 00 00 00`（目标 id 在偏移 2） |
| 6 | 采样名 | 4 字节 0 + UTF-16LE 名 + 0 填充 |
| 9 | 创建对象参数 | |
| 10 | 动画名 | |
| 16/17 | 按键值 | u32 键位掩码（fire 1 = 0x10，fire 2 = 0x20，方向 1/2/4/8） |
| 22 | 表达式 | 见下 |
| 23 | 比较表达式 | 开头 u16 = 运算符：0 `=`，1 `<>`，2 `<=`，3 `<`，4 `>=`（5 未证实） |
| 37/38/39 | 注释/组/循环等结构 | |
| 45 | 循环名 / 组名 | |
| 50 | 数值常量 | 6 字节：u32 值 + `00 00` |
| 53 | 可变量下标 | 16 字节表达式，目标下标在偏移 8 的 u32 |

## 3. 表达式（t22 / t23）

**未完全解析**。已知：

- 常量：16 字节 `0000 ffff 0000 0a00 <u32 值> 0000 0000`。
- 可变量/值引用、运算符都以不透明字节串出现，长度可变（16～70+ 字节）。
- 同一条公式在不同“分支”里只差 1～2 个字节。例如四个跳跃动作：

| 事件 | 语义 | 速度值字节 | 加速度下标 |
|---|---|---|---|
| `mario-movement` #167 | 跳跃初速度 − AltValN(103) | `0a` | `67 00 00 00` (103) |
| #170 | 游泳初速度 − AltValN(105) | `0b` | `69 00 00 00` (105) |
| #173 | 跳出水初速度 − 105 | `0c` | `69 00 00 00` (105) |
| #174 | 跳出水初速度（着地）− 105 | `0d` | `69 00 00 00` (105) |

**不要手工改写表达式内部**；按语义整段复制，并用“指纹”断言校验
（见 [opcode-cookbook](opcode-cookbook.md) §指纹）。

## 4. 元数据

### 4.1 `SMER`（事件注释）

`u32 条数` + 每条 16 字节左右（注释文本另存）。生成事件时写 `SMER 00 00 00 00`
即可；注释不是必需的。

### 4.2 `SJBO`（对象表）

`u32 对象数` + 每个对象：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | u32 | 事件记录里的 object id 引用它 |
| type | u16 | 2 = Active/`Sprite`；3 = Group；其它类如 `RYAL` = Layer object |
| 类编号 | u16 | 普通 Active/Group 为 2；Layer object 为 0x21。按样本原样保留 |
| 名称长度 | u32 | 字符数，高位置 1 表示 Unicode |
| 名称 | UTF-16LE | 粘贴时按名称匹配工程里的对象 |
| 类名长度 | u32 | 同上 |
| 类名 | UTF-16LE | 普通 Active 与 Group 都是 `Sprite` |
| flags | u16 | 1 = 该对象是本事件列表的主体；纯帧事件导出里全为 0 |
| 组 id | u16 | **仅 type=3**：限定符编号（见下表），无图标块 |
| 图标 | 4 字节 + 可选 | type=2 时：`OIC0` 无负载；`OIC2`/`OIC3` 后跟 u32 长度和负载 |

组（限定符）编号：Instance 0、Gravity 1、Movable 2、Solid 3、Platform 4、
Water 5、MarioAni 6、Enemy 7、Shell 8、HardShell 9、EnemyTurn 10、Lava 11、
PowerUp 12、MovingBlock 13、Block 16、AutoPlace 17。

### 4.3 `TYAL`

`u32 长度（62）` + 62 字节常量。所有样本逐字节相同，直接照抄，不要自造。

### 4.4 结尾

`!DNE`。

## 5. 对齐“可读文本”和二进制时的坑

`mario-movement.txt` 是同一份导出的人工转写，但：

- 顺序不保证 1:1 对应（注释、分组、被省略的注释事件都会错位）；
- 同一段文字可能对应多个结构相似的分支（跳跃就有 4 个）。

**先用结构定位，再用文本确认语义**：按 opcode、参数、深度、取反位找到候选，
最后用文本核对。不要按“第几条”直接数。
